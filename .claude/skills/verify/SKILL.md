# verify — проверки Tsudoi

Как в Hibiki, перед объявлением готовности выполни свежие автоматические проверки
и проверь затронутые пользовательские сценарии вживую.

## 1. Зоны и фактическое состояние

Проверь diff относительно main, незакоммиченные и новые файлы, затем соответствующие
карточки [карты](../../../.ai/map/README.md). Для начального репозитория без родителя
проверь staged-файлы и весь состав дерева.

Для документов и служебной основы проверь локальные ссылки, пути, симлинки,
frontmatter, исключения и diff. Для запускаемой заготовки выполни сборку,
проверку типов и HTTP-проверку страницы и `/health` в dev и собранной версии.
Для изменений конфигурации проверяй затронутый режим запуска.

## 2. Команды после появления продуктового кода

Строго по порядку, после последних изменений:

1. `npm test` — итог тестов и файлов. Тестовая БД отделена от пользовательской.
   Команда появляется вместе с первыми продуктовыми тестами.
2. `npm run build` — сборка приложения.
3. `npm run typecheck` — типы рабочих пакетов.

Окружение и запуск описаны в [dev-env](../../../.ai/map/dev-env.md).

## 3. Живые поверхности

| Зона | Что подтвердить |
|---|---|
| UI и аккаунты | Вход и регистрация по инвайту в браузере. Личный диалог и группа с отдельными сессиями. Проверка на телефоне и ПК. |
| Гости и права | Одноразовость, срок, отзыв, история с момента входа и изоляция других чатов. Для отзыва проверить открытую вкладку, прямую ссылку на файл и доставку событий. |
| Переписка | Доставка в открытый чат, непрочитанное, реакции, возврат после разрыва и повтор отправки без дубликата. |
| Вложения | Реальные тестовые файлы, GIF и стикер. Отправка, отображение, скачивание, лимиты, доступ и сохранность после перезапуска. |

Воспроизведи критерии соответствующей задачи. Для MVP сверь все сценарии из его
постановки. Используй отдельные браузерные сессии и синтетические тестовые данные.

## 4. Запись и отчёт

В verify.md задачи: команды, числа, фактический результат, что наблюдал,
ограничения и «Что посмотреть руками». Доказательства —
`storage/verification/NN-slug/` вне git. Для начальной основы без приложения
результат допускается записать в `.ai/history.md`.

Пароли, токены и рабочие данные остаются вне отчёта и git. Перед запуском проверь
порты и сохрани работающие соседние проекты.

Укажи проваленные и пропущенные проверки и причину.
